Building Nodes with Aaron

Aaron's API is composable and modular. Configure a control plane, scale worker nodes, run standalone local supervisors, or decouple services with the internal EventHub. 

// 1. Primary Coordinator: OpenRaft Consensus, Shard Orchestrator & Admin Console
use aaron::{
    admin::AdminService,
    control_plane::ControlPlaneService,
    membership::MembershipService,
    shard::ShardService,
    tracing::TracingService,
    Node,
};

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    // Initialize cluster subsystems on documented default ports
    let (membership_svc, membership_handle) = MembershipService::pair();
    let (control_svc, control_handle) = ControlPlaneService::pair();
    let (shard_svc, shard_handle) = ShardService::coordinator(control_handle.clone());

    let node = Node::new("orders-coordinator")
        .with(membership_svc)                                              // SWIM Gossip on default port 7946
        .with(TracingService::new())                                       // Dynamic log filter reload
        .with(control_svc)                                                 // OpenRaft consensus RPC on port 18946
        .with(shard_svc)                                                   // Shard placement coordinator
        .with(
            AdminService::new()                                            // Embedded Admin Web UI on port 8080
                .with_membership_handle(membership_handle)
                .with_control_plane_handle(control_handle)
                .with_shard_handle(shard_handle),
        );

    println!("Orders coordinator online. Admin console available at http://127.0.0.1:8080");
    node.run().await?;
    Ok(())
}

// 2. Application Worker: Receives ShardEvents from Control Plane & streams telemetry back
use aaron::{
    membership::{MembershipConfig, MembershipService},
    service_fn,
    shard::{MemberRole, ShardEvent, ShardService},
    tracing::TracingService,
    Context, Node,
};

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    // Join SWIM gossip mesh (port 7947 to avoid collision on localhost)
    let config = MembershipConfig::lan()
        .bind_addr("0.0.0.0:7947")
        .add_seed("127.0.0.1:7946");

    let (membership_svc, _membership_handle) = MembershipService::pair_with_config(config);

    // ShardService::worker() binds QUIC (18946), receives commands from Control Plane,
    // publishes ShardEvents to EventHub, and streams telemetry back to Control Plane
    let (shard_svc, shard_handle) = ShardService::worker();

    let node = Node::new("inventory-worker")
        .with(membership_svc)                                              // Gossip mesh discovery
        .with(TracingService::new())                                       // Observability service
        .with(shard_svc)                                                   // Shard listener & telemetry reporter
        .with(service_fn("inventory-storage", move |ctx: Context| {
            let shards = shard_handle.clone();
            async move {
                // Subscribe to reactive shard lifecycle events dispatched by ShardService
                let mut sub = ctx.event_hub.subscribe::<ShardEvent>().await;

                while let Ok(event) = sub.recv().await {
                    match event {
                        ShardEvent::Join { shard_id, members, role } => {
                            // Initialize local LSM keyspace partition for assigned shard
                            let store = ctx.store.keyspace(&format!("inventory_shard_{shard_id}"))?;
                            store.insert(b"status", b"active_partition")?;
                            ctx.store.persist()?;

                            // Notify local state & acknowledge role in shard quorum
                            shards.announce_role(shard_id, role).await;
                            println!("Assigned shard {shard_id} as {role:?} (Quorum: {} members)", members.len());
                        }
                        ShardEvent::RoleChanged { shard_id, role } => {
                            shards.announce_role(shard_id, role).await;
                            println!("Shard {shard_id} role updated -> {role:?}");
                        }
                        ShardEvent::Leave { shard_id } => {
                            println!("Shard {shard_id} decommissioned. Detaching keyspace.");
                        }
                        ShardEvent::Bootstrap { shards: batch } => {
                            println!("Bootstrapping {} partitions from Control Plane.", batch.len());
                        }
                    }
                }
                Ok(())
            }
        }));

    println!("Worker running. QUIC listener on :18946 • Telemetry streaming to Control Plane");
    node.run().await?;
    Ok(())
}

// 3. Standalone Supervisor: Local actor lifecycle & embedded LSM storage (No network required)
use aaron::{service_fn, Context, Node};
use std::time::Duration;

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    // Supervise local services with isolated LSM storage and graceful drain on SIGINT
    let node = Node::new("local-runner")
        .with(service_fn("metrics-collector", |ctx: Context| async move {
            let stats = ctx.store.keyspace("telemetry")?;
            let mut seq: u64 = 0;

            // Service loop drains cleanly when supervisor receives SIGINT/SIGTERM
            while !ctx.cancellation_token.is_cancelled() {
                tokio::time::sleep(Duration::from_millis(500)).await;
                seq += 1;
                stats.insert("heartbeat:ticks", seq.to_le_bytes())?;
                println!("Supervised collector heartbeat [seq={seq}]");
            }
            Ok(())
        }));

    println!("Standalone supervisor running. Press Ctrl+C for graceful drain.");
    node.run().await?;
    Ok(())
}

// 4. EventHub: Decoupled in-memory async pub/sub between supervised services
use aaron::{service_fn, Context, Node};

#[derive(Clone, Debug)]
struct OrderEvent {
    order_id: &'static str,
    amount_cents: u64,
}

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    let node = Node::new("event-driven-node")
        // Service 1: Asynchronous subscriber reacting to OrderEvent broadcast
        .with(service_fn("billing-worker", |ctx: Context| async move {
            let mut stream = ctx.event_hub.subscribe::<OrderEvent>().await;
            tokio::spawn(async move {
                while let Ok(ev) = stream.recv().await {
                    println!("Billing processed order {} for ${:.2}", ev.order_id, ev.amount_cents as f64 / 100.0);
                }
            });
            Ok(())
        }))
        // Service 2: Publisher emitting strongly-typed domain events
        .with(service_fn("order-gateway", |ctx: Context| async move {
            let hub = ctx.event_hub.clone();
            hub.publish(OrderEvent { order_id: "ORD-9901", amount_cents: 9950 }).await;
            Ok(())
        }));

    println!("EventHub node online. Services communicating over lockless bus.");
    node.run().await?;
    Ok(())
}

Architectural Philosophy

Opinionated Choices & Why

Instead of stitching together dozens of disparate infrastructure tools, Aaron makes deliberate architectural commitments designed to maximize resilience, zero-copy performance, and operational simplicity.

01 • Single-Binary Runtime

Autonomous Node Runtime

The Choice: Every node packages actor supervision, storage, discovery, and transport inside a single Rust binary.

Why: Standard clusters require deploying external caches, coordination sidecars, and separate storage daemons. With Aaron, you eliminate external moving parts: an autonomous production cluster forms simply by running instances of your compiled binary.

02 • Zero HoL Blocking

Multiplexed Stream Transport

The Choice: UDP-based multi-stream transport with mandatory TLS 1.3 encryption across all internal traffic.

Why: Traditional TCP connections suffer from Head-of-Line blocking—a single dropped packet stalls all logical traffic. Multiplexed byte streams allow thousands of concurrent exchanges over a single port where packet loss in one stream never degrades another.

03 • Bounded O(1) Load

Decentralized Peer Discovery

The Choice: Probabilistic gossip membership with direct & indirect probing and monotonic incarnation numbers.

Why: Centralized discovery registries become cluster-wide bottlenecks. Decentralized gossip keeps network overhead strictly $O(1)$ per node regardless of cluster size, while indirect probes prevent false-positive node evictions on transient network hiccups.

04 • Sub-Millisecond Disk

Log-Structured Disk Persistence

The Choice: Integrated embedded LSM storage with Write-Ahead Logging (WAL) and partition keyspaces.

Why: Storing state in external databases forces every state transition across a network hop. Embedded LSM storage delivers microsecond write latencies and sub-millisecond point lookups directly within the node process space without managing external databases.

05 • Zero Heap Copies

Zero-Copy Schema Framing

The Choice: Strict compile-time binary schemas with memory-mapped byte buffer offsets.

Why: Text formats like JSON and heavy binary deserializers burn CPU cycles allocating memory on the heap. Zero-copy framing enables reading incoming fields directly from raw network buffers via offset pointers in $O(1)$ time with zero heap allocations.

06 • Embedded Consensus

In-Process Quorum Consensus

The Choice: Leader-elected quorum consensus compiled straight into aaron-control-plane.

Why: While gossip handles eventual consistency for node health, linearizable coordination is required for shard rebalancing and cluster-wide metadata. In-process consensus provides strong consistency without running independent Raft server fleets.

Resilience & Transitions

Cluster Node Lifecycle

How nodes join the mesh, converge topology state, detect network partitions, and autonomously self-heal without manual intervention.

01
Bootstrap & Initial Discovery Initialization

The node allocates its network transport port, initializes local disk storage, and assigns its unique Uuid. If seed addresses are configured, it performs handshake probes against the seed; otherwise, it operates as the initial seed for subsequent peers.

02
Decentralized Peer Convergence O(log N) Dissemination

The gossip engine propagates the new node across the mesh in bounded random steps. Each node maintains an ordered local membership table and disseminates updates probabilistically via network datagrams.

03
Failure Detection: Direct & Indirect (Ping-Req) Suspect State

At configured probe intervals (e.g. 400ms), a node pings a random peer. Upon probe timeout (150ms), it recruits 3 neighboring peers to execute indirect ping-req probes. If unanswered, the target enters the Suspect state with a decay timer.

04
Incarnation Counter & Self-Refutation Self-Healing

If a node receives a Suspect rumor regarding itself while healthy, it increments its monotonic incarnation number and broadcasts an overriding Alive notification, neutralizing false-positive gossip immediately.

05
Graceful Drain & Shutdown Graceful Drain

During planned termination (SIGTERM / CancellationToken), async services drain in-flight requests, local LSM tables flush pending commits to disk, and the node dispatches departure notifications to peers to prevent false suspect alarms.
