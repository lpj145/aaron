The Opinionated Distributed Cluster Runtime for Rust

Aaron is engineered to build resilient, self-healing clusters in a single compiled binary. Autonomous nodes supervise internal services, persist state to embedded disk-backed LSM trees, discover peers through decentralized SWIM gossip, and stream zero-copy data over QUIC without external coordination daemons.

Code Models

Building Nodes with Aaron

Aaron's API is composable and modular. Configure a control plane, scale worker nodes, run standalone local supervisors, or decouple services with the internal EventHub. 

// 1. Control Plane Node: Raft consensus orchestrator with default configuration
use aaron::{
    admin::AdminService,
    control_plane::ControlPlaneService,
    tracing::TracingService,
    Node,
};

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    // Creates standard paired ControlPlaneService (OpenRaft consensus engine)
    let (control_plane, cp_handle) = ControlPlaneService::pair();

    // Compose node with Dynamic Tracing, Raft Control Plane, and Admin Console UI
    let node = Node::new("control-plane-01")
        .with(TracingService::new())                                    // Dynamic log reload
        .with(control_plane)                                           // Raft metadata state machine
        .with(AdminService::new().with_control_plane_handle(cp_handle));// Web dashboard on port 28100

    println!("Control Plane node active. Admin dashboard available at http://localhost:28100");
    node.run().await?;
    Ok(())
}
// 2. Worker Node: Joins the cluster mesh with standard SWIM gossip config
use aaron::{
    membership::{MembershipConfig, MembershipService},
    service_fn, Context, Node,
};

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    // Standard config pointing to seed node on port 18100
    let config = MembershipConfig {
        bind_addr: "0.0.0.0:18101".to_string(),
        seeds: vec!["127.0.0.1:18100".to_string()], // Connects to seed / control plane
        ..Default::default()
    };
    let (membership, _handle) = MembershipService::pair_with_config(config);

    // Node executes supervised business tasks alongside gossip failure detection
    let node = Node::new("worker-01")
        .with(membership)
        .with(service_fn("worker-job", |ctx: Context| async move {
            let store = ctx.store.keyspace("workloads")?;
            store.insert("job:001", b"completed")?;
            ctx.store.persist()?;
            Ok(())
        }));

    println!("Worker node online and participating in SWIM mesh.");
    node.run().await?;
    Ok(())
}
// 3. Standalone Supervisor: Local actor/service supervision without cluster networking
use aaron::{service_fn, Context, Node};
use std::time::Duration;

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    // Supervise local async services with graceful shutdown & embedded storage
    let node = Node::new("local-runner")
        .with(service_fn("metrics-collector", |ctx: Context| async move {
            let stats = ctx.store.keyspace("metrics")?;
            let mut ticks: u64 = 0;

            // Loops until the supervisor signals graceful shutdown via CancellationToken
            while !ctx.cancellation_token.is_cancelled() {
                tokio::time::sleep(Duration::from_secs(1)).await;
                ticks += 1;
                stats.insert("ticks", ticks.to_le_bytes())?;
                println!("Supervised heartbeat tick: {ticks}");
            }
            Ok(())
        }));

    println!("Supervisor active. Press Ctrl+C for graceful drain.");
    node.run().await?;
    Ok(())
}
// 4. EventHub: Decoupled in-memory async pub/sub between supervised services
use aaron::{service_fn, Context, Node};

#[derive(Clone, Debug)]
struct OrderCreated {
    id: u64,
    amount_cents: u64,
}

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    let node = Node::new("event-driven-node")
        // Service A: Asynchronous Subscriber reacting to OrderCreated
        .with(service_fn("billing-worker", |ctx: Context| async move {
            let mut sub = ctx.event_hub.subscribe::<OrderCreated>().await;
            tokio::spawn(async move {
                while let Ok(event) = sub.recv().await {
                    println!("Billing processed order #{} for ${:.2}", event.id, event.amount_cents as f64 / 100.0);
                }
            });
            Ok(())
        }))
        // Service B: Event Publisher dispatching strongly-typed messages
        .with(service_fn("order-gateway", |ctx: Context| async move {
            let hub = ctx.event_hub.clone();
            hub.publish(OrderCreated { id: 1001, amount_cents: 9950 }).await;
            Ok(())
        }));

    node.run().await?;
    Ok(())
}
Architectural Philosophy

Opinionated Choices & Why

Instead of stitching together dozens of disparate infrastructure tools, Aaron makes deliberate architectural commitments designed to maximize resilience, zero-copy performance, and operational simplicity.

01 • Single-Binary Philosophy

Autonomous Nodes

The Choice: Every node packages supervision, storage, gossip, and transport inside a single Rust process.

Why: Standard microservices require deploying Redis for caches, ZooKeeper/etcd for locks, and separate sidecars. With Aaron, you eliminate external moving parts: a production cluster is born simply by launching instances of your compiled binary.

02 • Quinn / Rustls

QUIC Multi-Stream Fabric

The Choice: QUIC over UDP with mandatory mutual TLS 1.3 encryption by default.

Why: TCP clusters suffer from Head-of-Line blocking—a dropped packet on stream A stalls all other streams. QUIC multiplexes thousands of independent streams over a single UDP port where packet loss in one stream never degrades another.

03 • Decentralized O(1)

SWIM Gossip Membership

The Choice: Decentralized probabilistic gossip with direct & indirect probing (ping-req) and incarnation counters.

Why: Centralized coordinators become single points of failure. SWIM scales with bounded $O(1)$ network load per node. Indirect probes eliminate false-positive evictions from temporary packet drops, while incarnation numbers allow self-healing.

04 • Disk-backed LSM

Embedded Fjall LSM Storage

The Choice: Integrated disk persistence with Write-Ahead Log (WAL) and logical keyspace isolation.

Why: Accessing state over an external network hop introduces milliseconds of latency. Fjall provides ~6 microsecond write latencies and sub-millisecond point lookups directly within the node process space without external database dependencies.

05 • Zero-Copy RPC

FlatBuffers Schemas

The Choice: Build-time schema generation via aaron-build and memory-mapped offsets.

Why: JSON parsing and Protobuf deserialization burn CPU cycles and trigger heap allocations. FlatBuffers allows reading fields directly from the QUIC network buffer via offset pointers in $O(1)$ time with zero heap copies.

06 • In-Process Raft

Embedded OpenRaft

The Choice: Raft consensus integrated directly inside aaron-control-plane.

Why: While gossip handles eventual consistency for 99% of node topology, linearizable consensus is required for shard assignment. Embedding OpenRaft lets consensus run as an Aaron service without managing external Raft daemons.

Resilience & Transitions

Cluster Node Lifecycle

How nodes join the mesh, converge topology state, detect network partitions, and autonomously self-heal without manual intervention.

01
Bootstrap & Initial Discovery Initialization

The node allocates its QUIC port, initializes local Fjall LSM storage, and assigns its unique Uuid. If seed addresses are configured, it performs handshake probes against the seed; otherwise, it operates as the initial seed for subsequent peers.

02
SWIM Gossip Convergence O(log N) Dissemination

The gossip engine propagates the new node across the mesh in bounded random steps. Each node maintains an ordered local membership table and disseminates updates probabilistically via QUIC datagrams.

03
Failure Detection: Direct & Indirect (Ping-Req) Suspect State

At configured probe intervals (e.g. 400ms), a node pings a random peer. Upon probe timeout (150ms), it recruits 3 neighboring peers to execute indirect ping-req probes. If unanswered, the target enters the Suspect state with a decay timer.

04
Dead Declaration or Incarnation Self-Healing Self-Healing

If the suspicion timer expires without refutation, the node is declared Dead and evicted from active routing. However, if the node was temporarily delayed or crashed and restarted, it refutes the suspicion by incrementing its incarnation counter, immediately restoring Alive status without cluster restarts.

05
Graceful Drain & Shutdown Graceful Drain

During planned termination (SIGTERM / CancellationToken), async services drain in-flight requests, Fjall LSM tables flush pending commits to disk, and the node dispatches departure notifications to peers to prevent false suspect alarms.
